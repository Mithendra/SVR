How to use this

  1. A user reports something wrong on a form — find its page below.
  2. Open the backend router, the frontend screen, and the tests named in that page.
  3. Add a failing test case, fix it, re-run pytest (backend) and npm test (frontend).
  4. One module per branch and commit, following the Daily Sales Entry pattern.

01

Daily Sales Entry

Built
Mockup
daily_sales_report_branded.html
Migration
0002_daily_sales_entry.sql
Access
Sales (own submission), Manager, Owner — delete is Manager / Owner only
Skill
skills/daily-sales-entry/

Purpose

Per-pump, per-shift sales entry — up to two a day, one per pump. Manual entry is live; Scan / OCR and Excel import share the same record and return 501 for now.

Form sections

  1. 1Gas Sale(s) — Pump · Current Reading · Last Shift Reading (auto @ 23:59 IST) · Cons[Last−Current] · Rate (locked Sell Rate HS/MS) · Amount · IOCL #
  2. 2Oil Sale(s) — 5 SKUs + “Add Oil Item”: Item · Quantity · Rate (auto, Rate Master) · Opening Stock (auto, Inventory) · Closing Stock · Amount
  3. 3Expenses — Description · Amount (accepts an inline sum, e.g. 527+588+100=1215)
  4. 4Credit Cards Swiping(s) — Card Holder / Terminal ID · Card Type · Rate · Transaction / Receipt # · Amount (rows add)
  5. 5Today New Credit(s) — Creditor Name · Type · In Ltrs · Rate · Amount · Signature
  6. 6Old / Pending Credit Received — Customer Name · Amount · Old Credit Given Date · Signature — not part of today’s total
  7. 7Summary — Cash Hand Off — Cash · Expenses · Phone Pay Settled / Not Settled · New Credits · Card Swiping · Night Cash · Net Bal Hand Off · Old Credit total
  8. 8Daily Summary — Total HS · Total MS · the 5 oil quantities (all auto-pulled from §1–2)

Key formulas

cons   = current − last          # blank until Current Reading entered
amount = cons × sell_rate         # Sell Rate, never Buy
oil    amount = qty × rate ,  closing = opening − qty
Net Bal Hand Off = (gas + oil) − expenses + phonePayNotSettled
                  + newCredits + cardSwiping + nightCash
round4 = JS Math.round ;  1317.52 × 105.36 = 138813.9072  (pinned by tests)

Owned by

api/daily_sales_entry.pycalc/daily_sales_entry.py calc/amounts.pycarry_forward.pyrates.py inventory.pyscreens/daily-sales-entry/ lib/calc-mirror.jstests/test_daily_sales_entry_api.py tests/test_calc_daily_sales_entry.py tests/daily-sales-entry.spec.js

Built

  • Manual entry + live calc engine (backend authoritative)
  • 23:59 IST carry-forward, gap-day skip-back, catch-up on startup
  • Sell-rate + carried-reading + inventory-opening snapshot on save
  • Print, Print Blank Form (per pump)

Deferred

  • OCR pipeline (Tesseract) — /ocr → 501
  • Excel import / export — → 501

Purpose

The link between the two pump sales men’s independent Daily Sales Entry submissions and Daily Trial Balance §3. Combines both once they are in and gates the upload behind a human verification.

Form sections

  1. 1Office Pump Submission — Pump Sales Man · entry mode · Verified dropdown · verification note · pulled HS / MS amounts + oil total
  2. 2Road Pump Submission — same shape as §1, for the other pump
  3. 3Combined Summary — Both Pumps — Office / Road / Combined per fuel + 5 oils + Grand Total — auto, feeds Trial Balance §3

Logic

combined line = office.amount + road.amount   # derived at read time, never stored
status: draft → verified (both pumps) → uploaded (Manager / Owner)
upload → 409 unless both submissions present AND both verified

Access

Purpose

The Owner-controlled Buy / Sell rates for Diesel (HS), Petrol (MS) and the 5 oil SKUs. Editing appends a new effective-dated row so historical records always resolve the rate that was active when they were created.

Form sections

  1. 1Update Rates — Item · Current Buy · Current Sell · New Buy · New Sell · Effective Date
  2. 2Rate Change History — Effective Date · Item · Old Sell · New Sell · Buy · Updated By

Definitions

Buy Rate  = what SVR pays IOCL per litre  (cost basis — Trial Balance §6)
Sell Rate = what customers pay at the pump  (Daily Sales Entry, Payment Receipt)
history “Old Sell” = previous effective row’s sell_rate  (LAG window)

Password Reset + Email

Built
Mockup
password_reset_branded.html
Migration
0010_password_reset.sql
Access
Any user (self-service) · Manager / Owner (admin-initiated, from Manage Users)

Purpose

Single-use, time-limited emailed reset link — both self-service and admin-initiated. The password value is never displayed, stored or transmitted; only the argon2 hash is kept.

Flow

request(login name or email) → always 202  # no account enumeration
      → token emailed, valid ~60 min, single use
“Set New Password” page: New Password · Confirm · live match check
confirm(token, new_password) → min 8 chars ; the user’s sessions are cleared
the Backend Service serves /password-reset.html itself  # link opens in a browser

Email backends

memory  # default; dev — echoes the link in the API response
file    # writes to data_dir/outbox
smtp    # prod — SVR_SMTP_HOST / _PORT / _USER / _PASSWORD, SVR_APP_BASE_URL

Purpose

The most formula-dense module — an 11-section daily reconciliation. This build models Sections 1, 3, 6 and 7; the rest wait on ADR-1.

Form sections (as numbered in the live sheet)

  1. 1IOCL Computer vs Pump Readings — modelled — Yesterday · Current → Diff, Consumption (from §3), Computer/Pump Diff, Benefit/Loss, Deduct Testing, Stock Ltrs
  2. 2Load / Unload Details — manual JSON
  3. 3Day Sales Report — modelled — HS / MS consumption pulled read-only from Daily Sales Summary
  4. 4Daily Cash & Bank Balances — manual JSON
  5. 5Cash / Book Value Reconciliation — manual JSON — 5.4 cash/book value feeds §7.1
  6. 6Stock Value — modelled — ltrs × Buy Rate
  7. 7Trial Balance — Actual Reported — modelled — 7.3 = 7.1 + 7.2
  8. 8Trial Balance — Projected vs Pump — manual JSON
  9. 9Daily Management Reporting — manual JSON
  10. 10Daily Mgr Calculation — 26-column running ledger — manual JSON
  11. 11Old / New Credit Sales Details · Fleet Card — manual JSON

Modelled formulas (SDD §9)

§1  diff = yesterday − current
     consumption = pulled from §3
     computer/pump diff = consumption − diff
     benefit/loss       = consumption + diff
     deduct testing     = consumption − 10        # system_parameter
§6  stock ltrs = diff − consumption           # sign PROVISIONAL
     amount     = ltrs × Buy Rate ;  total = HS + MS
§7  7.1 = today’s cash / book value (manual)
     7.2 = §6 total ;  7.3 = 7.1 + 7.2

Appendix

Roles

Exactly three. Every write is re-checked server-side (core/rbac.require), independent of what the screen shows, then recomputed, persisted and written to audit_log (core/audit.record_write).

RoleReach
SalesStation floor. Daily Sales Entry (own submission) and Payment Receipt only. No access to any other module.
ManagerBroad operations across every module, including delete of a submitted daily form. View-only on Rate Master.
OwnerAll Manager rights, plus the exclusive right to edit Rate Master, set the Yearly Report’s manual figures, add expense categories and change inventory reorder levels.

Retired forms

new_credit_entry_branded.html and record_repayment_branded.html were folded into Module 6 (Credit / Remittance Master) — §1 New Credit and §2 Remittance respectively. The files are kept for historical reference only.

Not a numbered module

The Home Page / navigation landing and the Login screen are the app shell — frontend/src/renderer/index.html + app.js (role-filtered nav) and backend/…/api/auth.py. A Sales session sees only its two permitted links.

Standing conventions (from CLAUDE.md)

Daily Sales Entry gas rows use Sell Rate, Trial Balance Stock Value uses Buy Rate. Last Shift Reading carries forward at 23:59 Asia/Kolkata. The backend calc engine is authoritative on every save; the renderer mirror is UX only. Frequently-revised constants live in system_parameter, versioned, not in code.
